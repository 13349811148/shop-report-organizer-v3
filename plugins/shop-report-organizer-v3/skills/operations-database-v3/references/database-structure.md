# V3运营数据库结构

```text
运营数据库/
├─ 1.产品数据库/
├─ 2.订单数据库/
│  └─ <店铺>/
│     └─ <年份>/<月份（成交时间）>/
├─ 3.售后数据库/
│  └─ <店铺>/<年份>/<月份（导出时间）>/
├─ 4.推广数据库/
│  └─ <店铺>/
├─ 5.运营操作日志/
├─ 6.商品ID库/
├─ 下载未分类/
└─ _系统/
```

## 固定用途

- `1.产品数据库`：全店共用产品主数据、物料/SKU明细、价格政策和成本历史。
- `2.订单数据库`：每店按业务月份维护累计订单表。
- `3.售后数据库`：每店维护累计售后表。
- `4.推广数据库`：每店按全店托管、商品推广分类保留原始报表，账户每日汇总单独保存；不分摊、不计算、不改写原始表格。
- `5.运营操作日志`：预览、正式整理、冲突、提醒及来源追溯。
- `6.商品ID库`：平台商品ID、样式ID、SKU ID与店铺/ERP商品编码的精确映射。
- `下载未分类`：只放待识别的原始导出。
- `_系统`：事务暂存、备份和内部状态；不得作为业务数据源。

不要在插件目录内保存店铺业务数据或私人商品映射。

## 后台指标

`7.后台数据库/<原文店铺>/<年份>/<月份>/` 保存后台MD转换的Excel；交易概况、体验与差评、流量数据按实际内容分别保存工作表，不保存来源说明工作表。原始MD存入该目录的“原始记录”，哈希凭据随Excel保存。仅转换、不计算，不覆盖其他店铺或历史版本。


## 京东原始报表

使用 `<业务数据库>/<店名（京东）>/<报表类别>/<年份>/<导出月份>/` 保存原始文件。订单统计期间取下单时间，售后保留两层表头，统计期间取售后申请时间。推广明细取日期列，现金和红包流水取投放日期。原表的统计期间、店铺归属证据与 SHA256 记录在同目录归档凭据。

| 业务数据库 | 京东报表类别 |
| --- | --- |
| 1.产品数据库 | 京东SKU原表 |
| 2.订单数据库 | 京东订单原表 |
| 3.售后数据库 | 京东售后原表 |
| 4.推广数据库 | 京准通推广明细、京准通现金消费、京准通红包消费 |

京东 SKU 归属取自同批有明确店名的 POP SKU 表或已校验的京东 SKU 归档。京东数据独立于拼多多和天猫的商品 ID 映射与累计表。消费账户仅显示「商家账户」时，使用已确认的 `--jd-shop` 参数。Excel 使用本次进程提供的密码只读校验京东加密订单。归档保存下载时的加密原件，密码仅用于当次读取。
